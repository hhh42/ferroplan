# Fortune 5 Capability Admission

This document is the operator-facing projection of `FP-PRD-F5-001` and `FP-ARD-F5-001`.

## Production claim

`Fortune 5 ready` is an internal ferroplan admission profile. It is not a claim of deployment at a Fortune 5 company, an external certification, or proof of suitability for an undisclosed workload.

A capability is production-admitted only for an exact source revision when every required evidence identifier in the canonical manifest is produced by a completed verification command and the independent `ferroplan-readiness` evaluator reports `ADMITTED`.

## Authority boundary

All planning outputs are candidate-only. Parse, validation, explanation, trace, and release reports are evidence-only or presentation-only. None grants actuation authority.

```text
candidate capability
→ bounded operation
→ independently validated output
→ external BRCE actuation
→ OCEL observed consequence
→ POWL conformance
→ Truex receipt/refusal
→ replay
```

The production profile does not collapse these stages.

There is no synthetic `fp.core.stream` capability. Internal progress signals do not constitute a public production streaming contract.

## Compatibility versus production

Compatibility APIs remain available for existing users. They are not automatically production-admitted.

Production integrations use the bounded surfaces:

```rust
solve_production
parse_production
validate_plan_production
explain_production
trace_production
decompose_production
solve_ppddl_production
ProductionSession
```

Every production envelope carries:

- schema version
- capability identity and version
- exact source revision when embedded by the build
- canonical manifest fingerprint
- domain-separated input fingerprint
- candidate/evidence authority class
- typed outcome
- independent validation status
- bounded counters and warnings
- typed public error

## Deadline law

In-process Rust surfaces enforce deterministic work, input, worker, policy, plan, and output limits. They do not claim preemptive wall-clock cancellation inside arbitrary caller processes.

`ferroplan-mcp-plus` adds a hard wall-clock boundary by running each untrusted computational request in a fixed worker-process mode, draining bounded output concurrently, and killing/reaping the worker when the deadline expires.

## MCP+ profiles

`ferroplan-mcp-plus` is the bounded production profile. Its fixed public tools are:

```text
plan
parse
validate
explain
readiness
version
```

It has no caller-selected command, shell, network, write, or actuation primitive.

`ferroplan-mcp` remains the broad compatibility and research server. Its larger tool surface is not promoted by the Fortune 5 admission report.

## Admission command

The verifier consumes evidence files generated by completed rails:

```bash
cargo run -p ferroplan --bin ferroplan-readiness -- \
  --source "$GITHUB_SHA" \
  --evidence target/fortune5/evidence.txt
```

Exit status:

- `0`: every shipped capability is `ADMITTED`
- `2`: evidence is incomplete
- `64`: verifier input is invalid

The manifest cannot set `ADMITTED`; only the evaluator can derive it.

## Release evidence

The exact-source admission rail requires:

- format, compile, Clippy, tests, docs, and benchmark compilation
- native Bevy build
- planner and Bevy browser builds
- Node execution of browser WASM
- Python wheel build/install/import/parity
- bounded MCP+ protocol, refusal, isolation, and deadline tests
- plugin lint, generated-file closure, tests, and verifier
- dependency vulnerability audit
- CycloneDX SBOM
- license inventory
- attributable release binaries
- SHA-256 checksums
- exact source identity
- independent final admission report

No subset is equivalent to full admission.
