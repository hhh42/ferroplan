# Chicago TDD Validation: Human Work Replacement

## Verdict

The statement **“this human work has been replaced forever”** is not directly
provable by test-driven development. `Forever` is an unbounded temporal claim.

The state-based claim that does stand is:

> Within the declared Ferroplan evidence-harvest boundary, repetitive human
> continuity work is replaced whenever exact-source observations, execution
> evidence, repository authority, and the verifier toolchain remain available.

Standing: **ALIVE for the bounded claim**.

## Why this is Chicago/classicist TDD

The acceptance tests use real collaborators and assert observable state:

- real `ObservationPack`, admission, operator, catalog, and receipt objects;
- real temporary filesystem boundaries;
- real PPDDL rendering, parsing, solving, and independent policy validation;
- real semantic operator deduplication;
- real BLAKE3 receipt identities;
- real clean-directory replay;
- no interaction mocks asserting which private methods were called.

The principal acceptance test is:

```text
chicago_tdd_replaces_the_bounded_human_continuity_function
```

Its counter-test is:

```text
chicago_tdd_preserves_the_human_authority_boundary
```

## Human work proven replaceable inside the boundary

The passing state contract demonstrates that Ferroplan can perform the following
without a person interpreting implementation details between stages:

1. collect and normalize execution evidence;
2. distinguish admitted work from unsupported claims;
3. discover equivalent procedures under different commit descriptions;
4. consolidate those procedures into one reusable planning operator;
5. generate the method catalog and PPDDL projections;
6. parse, solve, and independently validate the generated planning model;
7. assemble source identities, exclusions, results, and digests into a receipt;
8. replay the manufacture in a clean output directory;
9. compare exact artifact identities and assign standing.

This replaces the bounded portions of manual status collection, repository
archaeology, tribal-memory reconstruction, repetitive PPDDL authoring,
verification coordination, audit-packet assembly, and release evidence
preparation.

## Human work not proven replaceable

The counter-test removes execution evidence and requires the system to leave the
run `UNKNOWN`, emit `ExecutionNotObserved`, generate no PPDDL domain or problem,
and manufacture no planning operator.

Therefore Ferroplan does **not** claim authority to replace:

- choosing desired outcomes;
- defining ontology and policy;
- granting actuation authority;
- inventing missing execution evidence;
- assigning probabilities without observations;
- accepting irreversible social or organizational consequences;
- human accountability for the governing rules.

## Replacement law

```text
repeated continuity work + admitted evidence + bounded authority
    -> mechanically replaceable

missing evidence | missing authority | unbounded value judgment
    -> human-owned or explicitly refused
```

The validated conclusion is not “all software labor is gone.” It is:

> Software bureaucracy that consists of deterministic evidence collection,
> procedural memory, projection manufacture, verification, receipt assembly,
> and replay is no longer inherently human work inside this system boundary.
