# Ferroplan v26.7.29 — The Claude Projection Becomes Lawful

Ferroplan v26.7.29 turns the Chatman ecosystem's Claude Code integration from a powerful plugin into a bounded, generated, and mechanically governed managed-world projection.

The constitutional boundary is explicit:

> Claude Code is not the Chatman ecosystem. It is one managed-world projection of the ecosystem.

The release aligns configuration, observation, allocation, deterministic planning, reversible manufacture, validation, receipt replay, and protected actuation without allowing the Claude runtime to silently exceed its authority.

## Release law

The release preserves the Chatman equation:

```text
A = μ(O*)
```

where `O*` is admitted observation, `μ` is lawful manufacture, and `A` is an artifact with standing.

It also preserves the BRCE invariant:

```text
zero unreceipted actuation
```

Claude Code may observe, route, request, and manufacture reversible source changes. It does not define constitutional truth, independently validate its own claims, or publish without a grant bound to receipts.

Every projected artifact has an owner, a generator class, a validation law, and a drift consequence.

## Agent authority becomes mechanical

Agent roles are no longer separated only by prose.

The controller can route work but cannot edit source.

The RDF observer can inspect repository evidence but cannot manufacture changes.

The CMCA allocator can allocate admitted work but cannot plan or edit.

The Ferroplan planner can construct deterministic candidate plans but cannot actuate them.

The independent validator can exercise checks but cannot repair failures.

The receipt auditor can replay evidence but cannot publish.

The source manufacturer is the only role granted direct source mutation capability, and it runs in an isolated worktree.

Claude Code's current plugin-agent frontmatter is used to encode these ceilings with `tools`, `disallowedTools`, `maxTurns`, `effort`, `skills`, and `isolation` where applicable.

## Global LSP ownership is removed

The Chatman Phase Engine no longer registers `claude-code-config-lsp` as the language server for every JSON, Markdown, TOML, and shell file.

Claude Code routes LSP servers by extension rather than by a bounded path predicate. A plugin claiming those four extensions can suppress other language servers and exceed a configuration validator's intended authority.

`claude-code-config-lsp` remains available as a standalone marketplace plugin and as an explicitly invoked configuration-validation rail. It is not loaded by the main Chatman plugin as a repository-global LSP.

## Phase state is evidence-derived

The mutable phase snapshot is treated as a cache, not canonical truth.

Canonical standing is derived from:

- the observation event frontier;
- admitted receipts;
- the declared phase law;
- predecessor continuity;
- replayed phase effects.

Pending repository mutations produce an effective collapsed projection:

```text
observed × unallocated × unplanned × sealed × drifted × unknown
```

without allowing a hook event itself to become admitted truth.

## Knowledge Hooks preserve the observation boundary

Claude Code hooks produce bounded observation and intent candidates.

A hook event does not itself prove that the world changed lawfully:

```text
hook event ≠ admitted state transition
```

Per-tool events remain available for exact replay. `PostToolBatch` provides one bounded batch summary before the next model call. Configuration and worktree lifecycle events are recorded as observation candidates without silently raising standing.

## Protected actuation becomes structured

Protected Bash requests are projected into structured actuation intents containing:

- actor and session identity;
- operation class;
- target and argument digests;
- current phase and receipt frontier;
- expected preconditions;
- reversibility;
- required standing.

The existing command matcher remains a compatibility fence. The constitutional object is the actuation intent and its derived execution grant.

Protected operations include:

- push, merge, rebase, destructive reset, and forced clean;
- pull-request creation or merge;
- package publication;
- destructive recursive deletion;
- state-changing HTTP requests.

No protected operation is lawful until the intent is granted against an admitted receipt frontier.

## Claude Code loader epoch

The configuration law is reconciled against the current official Claude Code documentation observed for this release.

Important loader facts include:

- `defaultEnabled` is supported for opt-in plugins;
- plugin agents support mechanical tool restrictions and worktree isolation;
- plugin agents ignore `hooks`, `mcpServers`, and `permissionMode` frontmatter;
- project-scope plugins do not load background monitors;
- monitor activation can be deferred until a named skill is invoked;
- `PostToolBatch` fires once after a parallel tool batch;
- `SessionStart` matchers are `startup`, `resume`, `clear`, and `compact`;
- plugin `settings.json` accepts only `agent` and `subagentStatusLine`.

Unknown loader deltas remain `UNKNOWN`. The loader wins over an older modeled schema for loadability, while modeled conformance remains a separate claim.

## Standing vocabulary

- `ALIVE`: exact runtime and replay evidence establishes the complete stated claim.
- `PARTIAL_ALIVE`: a bounded subset is evidenced and remaining obligations are named.
- `BLOCKED`: an admitted dependency or authority prevents lawful progress.
- `BUILD_BROKEN`: an exercised build, validation, or runtime surface failed.
- `UNKNOWN`: required evidence or execution was unavailable.
- `UNSUPPORTED`: the requested capability is outside the current system boundary.

`UNKNOWN` is not admitted. `UNSUPPORTED` is not a runtime failure. Source presence does not establish execution.

## Known boundaries

### Independent semantic admission

No independent semantic oracle is wired. BCINR-CMCA remains the bounded allocator, pinned by revision. Semantic admission above bounded observation remains `UNSUPPORTED` until the MFW/POWL v2 rail and independently vendored validation evidence are connected.

### BRCE completeness

The Claude adapter manufactures structured intents and grants, but the complete cross-runtime BRCE broker remains a separate ecosystem milestone. The adapter is a bounded Gall checkpoint, not the entire broker.

### Crown standing

The repository changes in this release establish source and configuration materialization. `ALIVE` still requires exact-head runtime and replay evidence.
