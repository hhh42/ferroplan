# Migration Guide: v26.7.29

## Scope

This guide migrates an existing Chatman Phase Engine installation to the lawful Claude projection introduced in Ferroplan v26.7.29.

## Required Claude Code capability

The plugin uses current Claude Code plugin-agent and plugin-manifest capabilities, including:

- `defaultEnabled`;
- `tools` and `disallowedTools` in plugin agents;
- `maxTurns` and `effort`;
- `isolation: worktree`;
- skill-triggered monitors;
- `PostToolBatch` hooks;
- plugin `userConfig`.

Use a current Claude Code release. Older loaders may ignore newer fields and therefore cannot establish the release's mechanical authority claims.

## 1. Remove stale cached plugin copies

Claude Code caches marketplace plugins by resolved version. v26.7.29 introduces an explicit plugin version and changes component topology.

Disable or uninstall the prior plugin copy, then reinstall or update:

```text
/plugin disable chatman-ecosystem@chatman-ecosystem
/plugin uninstall chatman-ecosystem@chatman-ecosystem
/plugin marketplace update chatman-ecosystem
/plugin install chatman-ecosystem@chatman-ecosystem --scope project
```

The plugin ships with `defaultEnabled: false`, but Ferroplan's checked-in project settings explicitly enable it for the repository.

## 2. Remove global config-LSP ownership

The main Chatman plugin no longer registers `.json`, `.md`, `.toml`, and `.sh` with `claude-code-config-lsp`.

Delete any hand-added equivalent from user or project plugin configuration when it was added solely for the Chatman plugin.

The standalone marketplace entry remains available:

```text
/plugin install claude-code-config-lsp@chatman-ecosystem --scope user
```

Use that only when repository-wide extension ownership is intentional. The Chatman configuration skills can also invoke the validator explicitly without loading it as a global LSP.

## 3. Re-enter user configuration

Plugin `userConfig` values are read from user, managed, or `--settings` sources. Project-local `pluginConfigs` are ignored by current Claude Code versions.

Reconfigure optional checkout paths through plugin configuration:

```text
/plugin configure chatman-ecosystem@chatman-ecosystem
```

Supported values:

- `ferroplan_root`: optional Ferroplan checkout used to launch the combined MCP server;
- `config_lsp_root`: optional checkout used only for explicit configuration validation.

## 4. Restart the session

Plugin agents are loaded at session start. Agent tool ceilings and worktree isolation do not take effect in an already-running session.

Restart Claude Code after updating the plugin. Monitors also require a new session after plugin updates.

## 5. Verify agent authority

Open `/agents` and confirm the plugin provides:

- `chatman-ecosystem:ecosystem-controller`;
- `chatman-ecosystem:config-law-architect`;
- `chatman-ecosystem:rdf-observer`;
- `chatman-ecosystem:cmca-allocator`;
- `chatman-ecosystem:ferroplan-planner`;
- `chatman-ecosystem:source-manufacturer`;
- `chatman-ecosystem:independent-validator`;
- `chatman-ecosystem:receipt-auditor`.

The controller and non-manufacturing agents must not expose direct file-edit tools. The source manufacturer must report worktree isolation.

## 6. Reconcile old phase snapshots

v26.7.29 treats mutable snapshots as caches. Pending observation events can project an effective collapsed phase even when an older `phase-state.json` still contains advanced values.

Run:

```sh
python3 "$CLAUDE_PLUGIN_ROOT/scripts/effective-phase.py" \
  --project "$CLAUDE_PROJECT_DIR"
```

Inspect:

- `canonical_vector`;
- `effective_vector`;
- `pending_event_count`;
- `requires_admission`;
- `replay_limitations`.

Do not manually edit the snapshot to force agreement. Admit or refuse the pending frontier through the normal planning and receipt loop.

## 7. Regenerate projected configuration

Run the projection validator:

```sh
python3 "$CLAUDE_PLUGIN_ROOT/scripts/validate-claude-projection.py" \
  --plugin-root "$CLAUDE_PLUGIN_ROOT"
```

The validator checks:

- manifest topology;
- absence of main-plugin global LSP registration;
- opt-in enablement;
- monitor activation bounds;
- agent authority fields;
- ownership declarations;
- JSON syntax;
- required documentation and ontology surfaces.

Where ggen manufacturing is available, regenerate from the admitted ontology and profiles before validating. Do not repair projected files independently from their owners.

## 8. Verify MCP startup

The plugin now documents one combined `ferroplan` stdio MCP process. It exposes stateless planning, persistent sessions, CMCA allocation, and admission-envelope tools under distinct claim ceilings.

Use the plugin doctor:

```text
/chatman-ecosystem:doctor
```

A successful process start does not establish semantic independence or `ALIVE` standing.

## 9. Verify monitor behavior

Monitors no longer start unconditionally.

- Receipt-frontier monitoring starts when `self-host` is invoked.
- Phase-frontier monitoring starts when `phase-change` is invoked.

Project-scope plugins do not load background monitors under Claude Code's trust model. This is expected and must not be promoted into a failure unless the session claims monitor coverage.

## 10. Verify protected actuation

A protected command now creates a structured actuation intent.

Before frontier closure, the PreToolUse hook must refuse the operation and identify the intent digest and missing obligations.

After validation and receipt audit, generate a bounded grant through the publication skill. The command must still match the exact granted intent.

A grant does not prove that the command executed. The resulting tool event must be captured and later bound as execution evidence.

## Rollback

To return to the previous plugin behavior:

1. disable v26.7.29;
2. reinstall the previous commit-SHA version;
3. restart Claude Code;
4. do not reuse v26.7.29 grants or effective-phase projections as evidence for the older runtime.

The observation and receipt ledgers should be retained. They are evidence, not disposable cache.

## Migration standing

Migration is complete only when:

- the current loader accepts the plugin;
- all agents expose their intended tool ceilings;
- no main-plugin global LSP server is registered;
- the MCP server initializes;
- pending observation state is correctly projected;
- protected actuation refuses without a grant;
- the exact release commit has a replayable validation record.
